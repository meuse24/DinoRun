# Release folder

`dino.html` and `size-report.json` are generated by `npm run build`. Do not edit
them; change the readable root `dino.html` and rebuild. Full details:
[doc/RELEASE.md](../doc/RELEASE.md) and [doc/UPDATES.md](../doc/UPDATES.md).

## Publish a release (FTP)

1. Increase `BUILD` in the root `dino.html` and `CACHE_NAME` in `service-worker.js`.
   Changing only the HTML is not enough: hosted updates are pinned to the worker cache.
2. `npm run build`, then run the tests listed in `doc/RELEASE.md` (Verify).
3. `npm run deploy -- --dry-run` checks the delivery and shows the plan. It stops
   when the build is stale or the live worker already has this cache version.
4. `npm run deploy` uploads, in this order:
   - optional extras (`--also <file>`, for example `highscores-lib.php`),
   - `release/dino.html` as `dino.html`,
   - `service-worker.js` last, so no worker caches a mismatched game.
   It then compares SHA-256 hashes of both files over HTTPS.

Target: `https://meuse24.info/apps/dino/` (FTP directory `apps/dino/`, over FTP with TLS).

## Credentials

`ftp.txt` in the repository root is git-ignored and must never be committed. Format:

```
https://meuse24.info/apps/dino/dino.html
Server: <ftp host>
Username: <user>
Passwort: <password>
```

The first line sets the target directory. The password is passed to `curl` on
stdin, not as a command-line argument.

## Never upload

Configuration (`highscores.config.php`), `highscores-data/`, password files,
tests and docs. `--also` only accepts a fixed list: PHP API/admin scripts,
manifest, icons and songs.
